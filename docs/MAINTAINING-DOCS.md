# Maintaining AI-Pack Documentation

This document explains how to keep the Docusaurus documentation site in sync with the AI-Pack framework.

## Overview

The AI-Pack documentation site uses Docusaurus v3.9.2 and is automatically kept in sync with framework changes through:

1. **Migration Script** - `scripts/migrate-docs.sh` - Copies framework content to docs
2. **Sync Workflow** - `.github/workflows/sync-docs.yml` - Auto-runs migration on changes
3. **Deployment Workflow** - `.github/workflows/deploy-docs.yml` - Deploys to GitHub Pages

## Automatic Synchronization

### How It Works

When you push changes to `main` that affect these paths:
- `gates/**`
- `roles/**`
- `workflows/**`
- `quality/**`
- `templates/**`
- `README.md`
- `scripts/migrate-docs.sh`

The sync workflow automatically:
1. Runs `scripts/migrate-docs.sh` to copy content to `docs/content/`
2. Adds Docusaurus front matter with titles and sidebar positions
3. Escapes MDX syntax issues (curly braces in code blocks)
4. Commits and pushes changes to `docs/content/`

This triggers the deployment workflow, which:
1. Builds the Docusaurus site
2. Deploys to GitHub Pages at https://cortexa-llc.github.io/ai-pack/

## Manual Synchronization

If you need to manually sync the documentation:

```bash
# Run migration script
./scripts/migrate-docs.sh

# Fix MDX issues
find docs/content -name "*.md" -exec sed -i '' 's/```$/```text/g' {} \;

# Test locally
cd docs/website
npm run start
# Visit http://localhost:3000/ai-pack/

# Build for production
npm run build

# Commit changes
git add docs/
git commit -m "docs: sync documentation with framework changes"
git push
```

## Adding New Content

### Adding a New Gate/Role/Workflow

1. Create the markdown file in the appropriate directory:
   - Gates: `gates/XX-name.md`
   - Roles: `roles/name.md`
   - Workflows: `workflows/name.md`

2. Run the migration script:
   ```bash
   ./scripts/migrate-docs.sh
   ```

3. The sidebar will automatically include it (autogenerated sections)

### Adding a New Section

If you need a completely new documentation section:

1. Create content directory:
   ```bash
   mkdir -p docs/content/new-section
   ```

2. Add markdown files with front matter:
   ```markdown
   ---
   sidebar_position: 1
   title: "Page Title"
   ---

   # Content here
   ```

3. Update `docs/website/sidebars.ts`:
   ```typescript
   {
     type: 'category',
     label: 'New Section',
     collapsed: true,
     items: [
       {
         type: 'autogenerated',
         dirName: 'new-section',
       },
     ],
   }
   ```

4. Test and commit

## Migration Script Details

The `scripts/migrate-docs.sh` script:

### What It Does

1. **Cleans old content** - Removes outdated migrated files (preserves intro, getting-started, claude-code-configuration)
2. **Migrates framework files** - Copies from source directories
3. **Adds front matter** - Inserts Docusaurus metadata with:
   - `sidebar_position` - Numeric ordering
   - `title` - Extracted from first heading (quoted to handle colons)
4. **Creates index pages** - Generates overview pages for each section
5. **Creates integration guides** - Maintains integration documentation

### What It Preserves

- `docs/content/intro.md` - Manual homepage
- `docs/content/getting-started.md` - Manual setup guide
- `docs/content/claude-code-configuration.md` - Manual config guide

### What It Generates

- All `docs/content/*/index.md` files - Section overviews
- All migrated framework content with front matter

## Handling MDX Issues

Docusaurus uses MDX (Markdown + JSX), which can have issues with:

### Curly Braces in Code Blocks

**Problem:** Plain code blocks (` ``` ` without language) containing `{` or `}` are interpreted as JSX expressions.

**Solution:** Add language specifier:
```bash
# Before (causes error)
```
{
  "key": "value"
}
```

# After (works)
```text
{
  "key": "value"
}
```
```

The migration script and sync workflow handle this automatically by adding `text` to empty code fences.

### Front Matter with Colons

**Problem:** YAML front matter with unquoted values containing colons fails to parse.

**Solution:** Quote title values:
```yaml
# Before (fails)
title: Gate 05: Lean Flow

# After (works)
title: "Gate 05: Lean Flow"
```

The migration script handles this automatically.

## Troubleshooting

### Build Fails with MDX Error

**Symptom:** `Could not parse expression with acorn`

**Fix:**
```bash
# Find problematic files
grep -r "^{$" docs/content

# Add language to code blocks
find docs/content -name "*.md" -exec sed -i '' 's/```$/```text/g' {} \;
```

### Content Not Updating

**Symptom:** Changes to framework don't appear in docs

**Fix:**
```bash
# Check if sync workflow ran
gh workflow view sync-docs

# Manually trigger sync
gh workflow run sync-docs

# Or run migration manually
./scripts/migrate-docs.sh
git add docs/content/
git commit -m "docs: manual sync"
git push
```

### Sidebar Not Showing New Files

**Symptom:** New markdown file doesn't appear in sidebar

**Fix:**
- Ensure file has front matter with `title`
- Check file is in autogenerated directory
- Restart dev server: `npm run start`

### Broken Links

**Symptom:** Links between docs pages return 404

**Fix:**
- Use relative paths: `[Link](./other-page.md)`
- Or Docusaurus paths: `[Link](/docs/section/page)`
- Check build warnings for broken links

## Best Practices

1. **Always test locally before pushing**
   ```bash
   ./scripts/migrate-docs.sh
   cd docs/website && npm run build
   ```

2. **Keep manual docs in docs/content/**
   - Don't edit migrated files directly
   - Edit source files in gates/, roles/, etc.

3. **Use descriptive commit messages**
   ```bash
   git commit -m "docs: add new security gate"
   git commit -m "docs: update orchestrator role"
   ```

4. **Monitor workflows after pushing**
   - Check Actions tab for failures
   - Verify site updates within 2-3 minutes

5. **Keep dependencies updated**
   ```bash
   cd docs/website
   npm update @docusaurus/core @docusaurus/preset-classic
   ```
